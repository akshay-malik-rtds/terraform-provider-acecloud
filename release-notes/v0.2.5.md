## Data source correctness fixes

v0.2.5 fixes silently-broken fields across the provider's data sources. No state migration required for `acecloud_flavors` or `acecloud_images`. The `acecloud_vpcs` data source has a small schema change — see below.

### `data.acecloud_flavors`

- `gpu_count` now returns the actual GPU count (was always `0` due to a JSON tag mismatch with the upstream API).
- `is_hourly` now reads the actual hourly-billing flag (was always `false` for the same reason).

### `data.acecloud_images`

- `disk_format` now returns the actual format (e.g. `"raw"`, `"qcow2"`). Was always `""`.
- `container_format` now returns the actual format (e.g. `"bare"`). Was always `""`.
- `virtual_size` now returns the actual size in bytes. Was always `0`.

### `data.acecloud_vpcs` (schema change)

- **Removed:** `router_id` — this field was wired to a non-existent upstream key and always returned `""`. If you referenced `data.acecloud_vpcs.all.vpcs[*].router_id`, remove the reference.
- **Added:** `mtu` (int), `router_external` (bool, true for public/external networks), `shared` (bool, true for cross-project shared networks). These were available upstream but not surfaced by the provider.

### Other data sources

- `data.acecloud_routers` and the other list data sources now return an empty list (`[]`) rather than `null` when there are no matching records. Previously, applying `length(data.acecloud_routers.foo.routers)` in a config with zero routers would fail with a null-argument error.

### Migrating from v0.2.4

| Change | Action |
|---|---|
| `flavors.is_hourly` / `flavors.gpu_count` now return real values | No code change required — filters that previously matched nothing will now match the right things |
| `images.disk_format` / `images.container_format` / `images.virtual_size` now return real values | No code change required |
| `vpcs.router_id` removed | Remove `vpcs[*].router_id` references from your HCL |
| `vpcs.mtu` / `vpcs.router_external` / `vpcs.shared` added | Optional — use them where useful |
